Published September 17, 2026

The capture problem is a boundary problem.

Agent observability often starts with application logs and ends with an assumption: if the log looks complete, the traffic must be complete. That assumption fails when agents retry, fork subprocesses, switch protocols, or bypass the expected client.

September 19: real experiments, separate verdicts.

All eight Codex/Hermes matrix cases and both recorder-off/on cases have terminal results. Six matrix captures pass independent verification; five tasks score 1.0. Task correctness and evidence completeness are different measurements. Claude was excluded from this stage.

The audit traces 64 model calls and enumerates 66 unresolved cross-source associations. Hermes failures remain failures: three byte-matching SSE responses lack HTTP chunked terminators, and one cancellation delivered only a prefix. A local native-CLI fixture verifies the export correction without another paid experiment.

M1–M3 local technical acceptance is complete. After fixing the live-inspection race, the frozen replacement passed its own full five-hour run: 20 collectors, 6,000 successful calls, 112,647 events and 1,140 recording segments. Recovery, integrity, projection and final queue-drain checks all passed. The earlier failed hour is retained, not accumulated. Thirty coverage findings and the real-provider failures remain visible; this is bounded acceptance, not universal certification. GitHub publication is pending write access. The older metrics below remain bound to the September 16 release.

Record first. Interpret second.

iorec keeps immutable transport and lifecycle evidence separate from later semantic reconstruction. Correlation can improve. The original bytes and sequence do not change.

Start with one command.

Encrypted recording is the default. The key stays with the operator.

iorec keygen --output ./iorec.key

iorec run \
  --key-file ./iorec.key \
  --upstream https://api.openai.com \
  --provider openai \
  -- your-agent-command
