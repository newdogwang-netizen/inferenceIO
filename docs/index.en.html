Capture nearby. Inspect centrally.

The recorder preserves local evidence; the platform handles ingestion, parsing, and inspection. Collection and interpretation stay separate.

Deploy alongside agents in Kubernetes

The admission controller adds recording to selected Pods. Capture runs beside the agent; a separate sidecar uploads to the central platform.

Model requests pass through the local proxy to the original provider. Recording data is buffered, then uploaded to the platform.

Native tool hooks and process observations provide different levels of evidence. A generated script is not proof of execution.

The September 22 test used a real Kubernetes Pod and a simulated model: 3 calls, 2 sealed segments, 47 events, and 5 body objects with matching hashes.

The limits belong in the record.

A successful task is not proof of a complete capture. The default claim is best-effort; stronger transport claims require a separate successful audit within a defined scope.

Real-agent experiments, Kubernetes acceptance, and historical soak tests cover different environments. None is a blanket production certification.
