`iorec 0.1.0` is release-hardened for local, best-effort recording on Linux x86-64. It is not a host-wide or transport-complete inference monitor. Every manifest claim remains `best-effort`, regardless of process exit status or verifier profile.

## Shipped boundary

- Transparent command execution with process-group signal forwarding and exit-code preservation, plus optional pre-exec cgroup-v2 task/descendant assignment under an explicitly delegated current scope.
- Append-only, crash-recoverable event evidence with durable concurrent sync batching, matching writer/reader record limits, and atomic physical event/blob byte and blob-entry budgets, plus immutable content-addressed blobs. Optional `zstd-blocks` framing compresses bounded plaintext batches before encryption, authenticates their placement metadata, rejects decompression bombs, recovers torn tails, and remains transparent to legacy readers, inspection, verification, export, and upload paths.
- Per-run HKDF-SHA256 data-key isolation from an operator-held master key, XChaCha20-Poly1305 encryption for events and blobs, and AEAD authentication for the plaintext manifest of an encrypted run. The CLI requires a key by default; plaintext recording is available only through an explicit `--allow-plaintext` acknowledgement. Legacy direct-key runs remain readable.
- Streaming HTTP/1.1, SSE, and reassembled WebSocket endpoint proxying.
- Bounded, asynchronous capture queues and a 128 MiB global request-normalization reservation: recorder storage failure, queue pressure, normalization pressure, or quota exhaustion cannot abort a healthy proxied exchange and is recorded as capture loss or an explicit semantic gap.
- Codex, Claude Code, Gemini CLI, and Hermes ephemeral adapters; a versioned statically linked third-party Adapter SDK with detect/configure/parse/correlate host validation; authenticated lifecycle hook ingestion; opt-in bounded/fail-open Python and Node.js OpenAI SDK/runtime observers; session import; process/namespace discovery with executable TLS markers, explicit network-scan gaps, and late TLS-library changes; and conservative multi-source correlation.
- Privileged-helper protocol v2 with a pre-exec readiness barrier, exact target PID/executable-SHA-256/PID-tree-or-cgroup binding, trusted helper executable checks, cleared environment, bounded encrypted JSONL evidence ingestion, and explicit binding/queue/protocol/drop/final/exit gating. The bundled experimental eCapture v2.6.0 TLS bridge adds one qualified Linux/OpenSSL/HTTP/1.1 cell. The bundled experimental AgentSight v1.0.25 process bridge adds bounded cgroup-scoped process/file/network/coordination/memory evidence, but always declares incomplete coverage because that upstream does not count ring-buffer reservation loss. Neither upstream executable is bundled.
- A versioned preflight probe plan in every manifest, derived from explicit selections, passive runtime/TLS markers, intended protocols, and current pcap/eBPF/tool prerequisites. It treats static markers as hints and distinguishes unavailable from bridge-required candidates. Optional strict-schema policy rules can bind an exact OS/architecture and target/TLS fingerprint to a digest-pinned helper; no-match, equal-priority ambiguity, missing prerequisites, or helper change fails before target launch, and the selection evidence is persisted without broadening the helper's qualified matrix.
- An opt-in rootless Linux task-network boundary that preserves the target UID/GID while dropping all capabilities, disables DNS/IPv6, admits only loopback and the exact recorder gateway/port through a fixed nftables policy, captures all task IP egress with immediate-mode tcpdump, and verifies helper/policy/sysctl/counter state across the exact target window. It requires trusted user-namespace tooling and deliberately prevents unrelated network access.
- An experimental transparent variant for endpoint-incompatible Agents. It requires a complete launch-time non-loopback IPv4 snapshot, read-only private `/etc/hosts` bind mount, exact nftables DNAT, per-run in-memory TLS keys, temporary public-CA cleanup, bounded concurrent TLS handshakes, HTTP/1.1/HTTP/2/SSE/WSS ingress, and encrypted ingress/upstream key logging. Loopback and other unusable endpoints fail before target launch; every unrecognized resolver, trust, pinning, QUIC, auxiliary-egress, OS, and container cell remains explicit.
- Bounded explicit shared-host egress rules for auth, telemetry, update, and other endpoints. The target is stopped until a canonical exact-socket DNS snapshot is resolved and recorded; DNS/model/cross-class conflicts fail launch. Local inspection and the connected platform fail closed on malformed classes and preserve unknown/model-bypass gates.
- Integrity, client-evidence, and transport-evidence verification profiles without upgrading the manifest claim.
- A bounded offline transport auditor that uses a trusted fixed-path TShark 4.4+ to reconstruct HTTP/1.1 and multiplexed HTTP/2 from encrypted pcap (plus TLS keys when the captured leg is encrypted), compare canonical request/response body multisets to proxy evidence, and publish a private hashes-only report. Schema v3 names its narrow completeness boundary as `target-network-namespace-ip-transport`; payload agreement and transport completeness are separate results.
- Raw evidence bundles, credential-free replay bundles, OpenInference semantic JSONL, OTLP/HTTP protobuf-JSON request bodies, pcap export, TLS key-log export, privileged-probe JSONL export, timeline, and state-reference analysis.
- Versioned logical-task reconstruction for long-lived multi-session Agents: explicit native `task_id` takes precedence over the conservative `session_id` fallback, while one physical run and its global sequence remain intact. The task dimension is preserved through correlation, bounded CLI inspection, semantic/replay exports, segmented platform processing/query, and the Web console.
- Direct HTTPS platform upload with private file-based credentials, short-lived in-memory collector sessions, immutable blob transfer, deterministic zstd batches, global durable-sequence reconciliation across contiguous Recording segments, bounded retry, crash-safe idempotent resume, manifest-bound final sealing, and collector heartbeat/config reporting. Upload-configured runs are retention-gated until every segment for every target is fully ACKed and sealed.
- A persistent collector now keeps a stable credential-free local identity/config state, refreshes short-lived sessions, heartbeats while idle, automatically uploads finalized runs, applies bounded restrictive config only to new runs, and executes crash-resumable control requests. Platform request delivery uses a lease and redelivers ACKed work after collector restart. Active-run `flush`/`seal` journal an exact writer-confirmed durable boundary before side effects and replay it after a crash; automatic size/age rolling starts the next segment at the following global sequence. Sequence-range backfill expands to immutable batch boundaries and force-republishes exact batch/blob bytes after object loss. Remote TTL and class-only `delete_local` require explicit local enablement and a fully ACKed/sealed target chain. An authenticated whole-run `delete_local` remains locally policy-gated but deliberately overrides upload completion so offline or partially uploaded evidence cannot become undeletable; deterministic quarantine recovery and request-scoped hash-chain audit cover both paths.
- New encrypted runs use three random class data-encryption keys, wrapped by the derived run key, for `body`, `pcap`, and `tls_secrets`. Local CLI TTLs, accepted platform TTLs, and class-qualified `delete_local` requests share an authenticated crash-resumable erasure state machine. It verifies the manifest, upload retention gate, writer exclusion, key envelope, ciphertext convergence, and audit chain; inspection distinguishes pending from completed erasure. The receipt proves cryptographic erasure of the live run namespace and explicitly denies physical-media guarantees.
- Platform coverage recomputation fails closed: zero observed counters and a sealed Recording are insufficient for a complete claim. A versioned server-side `transport_audit` stage now verifies exact runner boundary reports and pcap/key-log objects, reconstructs H1/H2 with a locally pinned TShark, persists a hashes-only proof, and triggers coverage recomputation. Coverage accepts only the exact current proof schema/boundary/processor version with source-boundary and payload-diff success and zero gaps. Ordinary upload deliberately omits pcap/TLS-secret tiers, so those runs remain `best-effort`; a platform proof can currently succeed only after an operator-controlled plaintext platform-bundle import supplies the sensitive evidence.
- Platform-owned retention and erasure use durable deletion-request/object queues with takeover leases, ingestion/job/control/read fencing, project-scoped blob reference accounting, object-before-fact cleanup, append-only audit, and minimal Recording/CaptureRun tombstones. Prefix discovery recovers batch/export objects and blob references that were published before a database crash. Blob uploads persist an `uploading` intent before object publication under the same project lock; failed unreferenced intents are retriable and audited before bounded garbage collection. Automatic `delete_local` requests do not expire while a Collector is offline; rejected local policy can be corrected and retried. Because immutable batch bytes can cross logical boundaries, Recording and Session deletion deliberately escalates to the containing CaptureRun instead of making an unverifiable narrow-erasure claim. Raw-evidence TTL scrubs batches, unshared blobs, exports, and body-derived fields while retaining metadata; metadata TTL reuses the full deletion chain.
- A deterministic, private, platform-importable plaintext tar export for encrypted runs, with complete evidence verification, atomic no-overwrite publication, and a 5 GiB hard bound matching the importer.
- Whole-run retention preview/deletion, legacy manifest migration, and a local hash-chained operations audit.
- A loopback-only performance/soak harness with encrypted workload generation and automatic count, drop, blob, tail, and integrity validation.

## Gates deliberately not claimed

- The Adapter SDK v1 contract is statically linked and process-local. It validates all four operations and catches unwinding panics, but reviewed third-party adapter code remains inside the recorder trust boundary; there is no runtime dynamic-module loader or killable out-of-process sandbox.
- The AgentSight process bridge and eCapture OpenSSL bridge each have only one qualified Linux x86-64/kernel cell; eCapture GoTLS additionally has exact Go 1.24.13 and 1.25.13 generic-client cells on that host. AgentSight v1.0.25 process coverage is permanently incomplete under its unobservable ring-buffer loss path. AgentSight TLS, other Go releases, named Go Agents, GnuTLS, NSS, BoringSSL, HTTP/2 GoTLS interpretation, arm64, containers, and other kernels remain unqualified. The planner and manifest do not upgrade those surfaces from hints or configuration intent.
- Transparent interception for endpoint-incompatible Agents is implemented but remains experimental. Rootless proxy-only task egress can prove absence of successful non-proxy IP egress in its declared namespace boundary; transparent mode adds exact model-socket DNAT and recorder-owned TLS termination without opening DNS or auxiliary egress. Both intentionally block auth/telemetry/update endpoints and have only a Linux x86-64 helper/kernel regression cell. Custom DNS/trust stores, certificate pinning, QUIC/HTTP3, containers, arm64, macOS, and real-provider matrices remain unqualified.
- Default pcap still uses a launch-time upstream-address snapshot. Only the explicit `--task-netns` mode binds capture and enforcement to the target namespace; shared-host captures remain ineligible for transport completeness.
- Auxiliary egress classes are exact launch-time DNS/IP/port snapshots. They prevent expected OAuth, telemetry, update, and operator-declared traffic from being mislabeled unknown, but do not verify SNI/hostname ownership, authorize traffic, or make shared-host discovery complete.
- HTTP/1.1 and HTTP/2 offline TLS decryption/reassembly and exact proxy-to-wire body diff are implemented. Proxy-only HTTP/1.1 and transparent HTTPS task-egress cells return complete and the bypass negative returns incomplete locally; the current platform-owned proxy-only HTTP/1.1 qualification also preserves the bypass downgrade in final coverage. Broad TLS/provider/platform matrices, WebSocket wire reconstruction, and Agent-specific client completeness remain incomplete.
- OTLP/HTTP protobuf-JSON request bodies are exportable, but active OTLP collector transport and binary protobuf transport are not implemented. The native `iorec-platform` batch uploader is separate and shipped.
- Retention deletes whole local runs or independently erases `body`, `pcap`, and `tls_secrets` class keys/ciphertext; the connected platform now owns its remote object/fact deletion path. Authenticated state and audit prove operation ordering and live-namespace convergence, but blob compression, remote WORM audit anchoring, physical-media erasure, and deletion of external PostgreSQL/S3 backups remain deployment responsibilities.
- Replay bundles reconstruct captured HTTP client requests and response comparison oracles, but do not make model generation deterministic or snapshot external URL dependencies.
- Managed multi-node deployment certification and Linux arm64/macOS/Recorder-or-Agent-in-container matrices are not available. This limitation does not apply to the platform services themselves: the qualified local Linux x86-64 API/Worker/Web Compose images are hardened and integration-tested, but they do not qualify an Agent running inside a container. The operator-approved five-hour duration supersedes the draft roadmap's 24-hour duration. Earlier invalidated attempts remain explicitly non-qualifying; the final core and 20-collector reports bind the rebuilt artifacts and have passed. Quantified overhead applies only to the exact binary hash and environment documented in `PERFORMANCE.md`.
- The final platform qualification uses the shared immutable filesystem object backend. The S3 adapter implements conditional publication and post-write verification, but AWS S3/MinIO/GCS compatibility is not live-qualified for this release and only static V4 credentials are supported; workload identity and a managed multi-node object-store matrix remain outside the release claim.
- Platform collector and project credentials, query filters, and object keys enforce project isolation. Static-user and OIDC identities currently resolve only to the deployment's configured default tenant/project; in-process user project selection and OIDC group-to-project mapping are not implemented. Multi-project user deployments must isolate instances until that authorization mapping exists, and request fields must never be treated as scope.
- The bundled SPA verifies no OAuth redirect or refresh flow of its own. Production browser access requires an OIDC-aware ingress that authenticates the browser and injects a bearer token which the API verifies again. Manually persisted browser tokens are limited to controlled local/operator use; that mode intentionally lacks authenticated native EventSource and direct blob-link navigation and must not be treated as PHI-ready SSO.
- Local log rotation is intentionally bounded at 20 MiB × 5 in the qualified Compose profile. Production operators must export logs to durable centralized storage before local rotation; this repository does not claim a bundled remote log archive.

The roadmap's functional v0.3/v0.5 requirements, exact declared support cells, two exact-current five-hour steady-state gates, final-hash performance rerun, real-Agent rerun, and post-run audits are implemented and verified; v1.0/M7 release qualification is closed for the documented Linux x86-64 boundary. Manifests remain `best-effort`. Within the explicitly isolated `--task-netns` boundary, only a zero-exit `transport-audit` report may be used as the narrower proof of transport completeness; default endpoint/shared-host capture must not be treated as proof that all model traffic was observed.
