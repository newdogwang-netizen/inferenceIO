# Security model

`iorec` records high-value model inputs, outputs, tool data, process metadata, packet bytes, and possibly TLS traffic secrets. Treat a run like a credential-bearing incident artifact.

## Defaults and invariants

- The CLI refuses to create a plaintext recording unless `--allow-plaintext` is supplied explicitly. Normal operation requires a private `--key-file`; the plaintext override exists for controlled debugging and is recorded as a coverage gap.
- Run directories and blob directories are mode `0700`; created evidence and keys are mode `0600`.
- Key files must be regular, non-symlink files inaccessible to group and other users.
- The private key file is a master key. Every new encrypted run derives an independent 256-bit run key with HKDF-SHA256 and a length-delimited `run_id`; the manifest records the master-key ID and exact derivation version. XChaCha20-Poly1305 encrypts event records with that run key and wraps three random per-run keys for the `body`, `pcap`, and `tls_secrets` blob classes. Event AAD binds the run ID and sequence; wrapped-key AAD binds the class; blob AAD binds the content hash. Per-run and per-class key separation prevents cross-run substitution and prevents equal plaintext in different classes from sharing ciphertext or a deletion fate.
- New class-keyed blob names carry their class, and the manifest authenticates the `random-class-dek-wrapped-by-run-key-v1` layout declaration. Readers reject a declared layout with a missing key directory, an undeclared key directory, class/ref mismatches, missing live class keys, and hash/size/scope violations. Legacy run-key blobs remain readable, but selective class erasure rejects them rather than making an unverifiable partial-deletion claim.
- Encrypted-run manifests authenticate their canonical content with XChaCha20-Poly1305 AAD and the derived run key while retaining the master-key ID as the operator-facing identity. Legacy manifests without a derivation field continue to use the supplied key directly; unsigned encrypted manifests remain readable but are reported and can be upgraded with `iorec migrate`.
- Evidence readers reject final-component symlinks, cross-run records, sequence gaps, non-UUIDv7/duplicate/decreasing event IDs, mixed plaintext/encrypted event logs, blob encryption-scope violations, and content hash/size mismatches. Optional zstd event blocks are bounded before decode and after decompression; encrypted blocks authenticate their run/sequence/count/size/digest context, and a run cannot silently switch physical formats. Ordered UUID validation uses constant memory even for long runs.
- Agent session discovery treats an absent session root as empty, rejects symlink or non-directory scan roots, and does not traverse symlink entries.
- Target fingerprinting opens only non-symlink regular files with nonblocking semantics, rejects files over 512 MiB, and verifies file identity/size/timestamps before accepting the hash. An unavailable or unstable fingerprint becomes a coverage gap and does not stop an otherwise executable target.
- Ordinary events filter credential-shaped headers, URL-bearing redirect/link headers that can contain presigned URLs, and recursively redact credential-shaped JSON fields. Filtering affects evidence snapshots only; proxy forwarding remains byte-for-byte at the header-value level.
- Untrusted JSON inputs are structurally preflighted before deserialization (64 nesting levels and 100,000 structural tokens). Stored records add a fixed 16-level/4,096-token recorder-wrapper allowance with matching writer/reader enforcement. Recursive sanitization is consuming rather than copy-on-write and retains at most 100,000 nodes, 10,000 items per container, and 1,024 redaction paths; reaching a safety bound is explicit capture loss, not silent success. The hook collector admits at most eight concurrent 16 MiB submissions.
- Metadata-only capture cannot retain hook/session bodies indirectly through normalized events: hooks keep only their value kind and top-level item count, and session readers keep a bounded lifecycle summary. Full request/response bodies and sanitized hook/session bodies require full-body policy.
- Free-form normalized model, state-reference, SSE, media-type, and URL strings cannot exceed 1 KiB or contain terminal controls. Values outside that envelope become deterministic length-bearing SHA-256 placeholders, preserving state correlation without retaining the original metadata; query-key arrays retain at most 128 names and report their complete count.
- Native hook submissions are target-controlled even though they carry the per-run collector token. Their sources are persisted under `hook:<source>`, recorder-reserved source names are rejected, caller-supplied evidence labels are marked as hook claims, and coverage/export analyzers accept transport, process, correlation, pcap, and TLS lifecycle semantics only from their recorder-owned sources.
- `--python-inject` runs recorder code inside the target interpreter and remains in that target-controlled tier. The private content-hashed shim has no third-party Python dependency, applies credential-key redaction before the collector's mandatory policy, and uses a bounded fail-open queue. A startup event proves loading only for that interpreter; unsupported SDKs, mutation, alternate runtimes or network stacks, and non-instrumented descendants remain gaps. Runtime self-reported loss can only lower coverage and never establishes transport completeness.
- `--node-inject` likewise executes a private content-hashed CommonJS preload and ESM loader inside the target. It preserves existing `NODE_OPTIONS`, has no third-party dependency, bounds its queue, sender deadline, structure, strings, binary values, records, and cloned fetch response streams, and applies camelCase-aware credential-key redaction. Worker/fork inheritance is tested, but target environment removal, older Node ESM-loader support, direct ESM `undici`, frozen/mutated SDK objects, native code, unsupported SDK versions, and non-Node descendants remain gaps. The loader deliberately changes the module facade returned for the bare `openai` ESM specifier, so it is opt-in and experimental. Its events are target-controlled and cannot establish transport coverage.
- Hook source/event labels, correlation IDs, evidence counts, and confidence values are validated before sanitized hook payload bytes enter the blob store, so a rejected envelope cannot leave a payload orphan behind.
- The inference proxy accepts only loopback listeners. Upstream bases must be absolute HTTP(S) URLs without userinfo, query strings, or fragments. Provider credentials belong in forwarded authentication headers, whose ordinary-event snapshots are always redacted; proxy failures log only a stable error class rather than a potentially credential-bearing URL.
- The programmable fake model server is test-only and refuses non-loopback listeners. It streams request hashing, caps concurrent requests, uses a single-chunk response queue per connection, bounds retained fault identities and response generation, and aborts after a bounded graceful-shutdown interval.
- Recorder failure events and internal stderr logs persist only stable error categories, safe I/O error kinds, and task failure state. The CLI prints only its outermost bounded diagnostic; credential-shaped or URL-bearing summaries are replaced wholesale, and terminal control characters are never emitted.
- Timeline results are cursor-paged (10,000 by default, 100,000 maximum), logical-task reconstruction caps both task identities and task/session associations at 100,000, state analysis caps each tracked category at 100,000 observations and declares omissions unresolved, and correlation caps its global anchor/transport indexes at 100,000 while ambiguous records retain at most 1,024 candidate IDs with the full candidate count. Inspection caps identifier indexes at 100,000 and blob references/directory entries at 250,000. OpenInference and replay accept at most 100,000 attempts; OpenInference drops in-memory payload references after its 16 MiB/100,000-chunk attribute boundary and bounds sequence arrays, while exact replay rejects attempts beyond 100,000 evidence items. Session discovery scans at most 100,000 entries. Exact analyses fail with `analysis_limit` rather than silently truncating truth.
- Packet, TLS-key, and privileged-probe plaintext capture cannot rely on ordinary field redaction, so all require at-rest encryption and explicit private-file export.
- `--task-cgroup` operates only beneath the invoking process's current cgroup-v2 membership. It creates a run-unique child, waits until the target is demonstrably stopped, writes the PID as one kernel command, and only then releases the launch barrier. It never changes controller configuration or deletes a parent/sibling. Missing delegation fails before the target executes; live members or unverifiable cleanup remain explicit capture loss. Cgroup membership scopes processes but does not enforce network policy.
- TLS FIFO shutdown has priority over readable input and its pending buffer is capped at 64 KiB. TLS, process-tracker, pcap-reader, collector, proxy, and fake-server shutdown paths have explicit deadlines. The pcap helper's stderr is always drained, retains only the final 64 KiB, reports omitted bytes, and makes such a capture incomplete; neither channel can grow memory without bound under continuous input.

Keep master keys outside run directories, back them up separately if recovery is required, and never commit them. Use distinct master keys for tenants or security domains. Supplying a new master key rotates future runs without rewriting historical evidence; keep prior keys for their retention lifetime. Loss of a master key makes every run under it unrecoverable, while compromise of one master key exposes all runs derived from it.

## Trust boundary

The target command runs as the invoking user. `iorec` does not sandbox an untrusted target: that process can read same-user environment variables, discover its run directory, or attempt to modify same-user files. The per-run collector accepts only the owning UID plus a constant-time-checked 64-byte token, bounds submissions/concurrency, prioritizes shutdown, and only unlinks the exact Unix socket inode it created; a colliding non-socket file is never removed. Events and blobs are encrypted in the default admitted configuration; `manifest.json` remains plaintext so operators can see run metadata and coverage without decrypting payloads, while encrypted runs AEAD-authenticate that plaintext manifest. AEAD and structural validation detect many modifications, but no artifact is digitally signed and a same-user adversary that obtains the applicable master key can derive the run key and forge evidence. The explicit plaintext override forfeits these properties.

Use a dedicated OS account or container boundary when recording untrusted code. Do not run the Agent itself as root. If packet/eBPF capture needs privilege, isolate that capability in a separately reviewed helper. The release bundles privileged-helper protocol v2, a readiness barrier, and experimental digest-pinned eCapture and AgentSight bridges; it does not bundle either upstream executable. `--probe-helper` requires a canonical non-symlink executable owned by root or the recorder user under protected ancestors, plus run encryption. The target is stopped before `exec`; the helper receives the exact target PID, canonical executable path and SHA-256, and requested PID-tree/cgroup scope, and must independently verify and echo that binding after its filter is active. Its environment is cleared, raw messages are bounded/encrypted, and every binding/queue/protocol/drop/final/exit failure degrades coverage. Graceful stop signals only the bridge so it can drain its source; a fixed timeout kills the full helper process group.

The eCapture bridge accepts only cgroup filtering, pins the upstream executable hash, rejects writable/symlinked trust paths, and consumes synchronous debug/hex output because the upstream WebSocket hub has unacknowledged drop paths. Configuration, payloads, diagnostics, input lines, per-event hex text, its 1,024-line queue, and its one-million-entry PID/connection tables are bounded; limit crossings and zero probe hits are explicit gaps. Its child must be installed behind a separately reviewed privilege boundary. The tested Debian 13 host required `CAP_DAC_OVERRIDE`, `CAP_NET_ADMIN`, `CAP_SYS_PTRACE`, `CAP_SYS_ADMIN`, `CAP_SYS_RESOURCE`, `CAP_PERFMON`, and `CAP_BPF` for eCapture v2.6.0 despite the upstream text-mode guidance naming a smaller set. `CAP_SYS_ADMIN` is broad: prefer a narrowly contained system service or dedicated host, and do not grant those capabilities to `iorec`, the bridge script, or the Agent. Qualification is limited to the matrix recorded under `benchmarks/`; unsupported runtime/kernel combinations remain best-effort.

The AgentSight bridge likewise requires cgroup filtering, exact executable digests, protected paths, a fixed upstream command line, bounded queues/events/PID history, and a positive upstream clock-start anchor before readiness. In `sudo-noninteractive` mode it accepts only canonical root-owned `sudo` and AgentSight files under entirely root-owned non-writable ancestors; no prompt is possible, but the operator must still constrain sudo policy or isolate the root process in a service boundary. Exact AgentSight JSON can expose command lines and filenames and remains encrypted until explicit probe export. AgentSight v1.0.25 does not expose process ring-buffer reservation loss, so the bridge always records a gap and never claims complete capture. The observed high-level shutdown also omitted the raw end anchor. Do not interpret a clean target exit or integrity pass as complete process monitoring.

The direct `tcpdump` path separately accepts only fixed system locations after verifying root ownership, execute permissions, non-writable parent directories, and a non-symlink regular target. Neither path resolves an executable through caller-controlled `PATH`.

## Plaintext exports

`pcap-export`, `tls-keys-export`, and `probe-export` create mode `0600` plaintext. Probe export admits only accepted protocol event names and revalidates each JSON object/type against its event envelope; rejected raw helper messages remain encrypted. Probe JSONL may already contain decrypted Authorization headers, cookies, prompts, files, and responses; a pcap plus matching TLS keys can reveal the same material. Move, retain, and delete all three under the same policy. `transport-audit` temporarily materializes both sensitive artifacts in a private mode-`0700` directory, invokes only a root-owned non-writable fixed-path TShark with a cleared environment and bounded time/output, removes temporary plaintext on every normal return path, and atomically publishes a mode-`0600` hashes-and-lengths report without body or query values. A crash or hostile decoder can still leave sensitive temporary files until the private temporary directory is removed, so run it only on a protected host.

Whole-run pruning and independent `body`, `pcap`, and `tls_secrets` TTLs are available. Class erasure requires a finalized, authenticated, class-keyed run; any configured upload must be fully ACKed and sealed, and the writer lock must be free. The state machine persists an encrypted intent before removing the wrapped class key and exact class ciphertext, syncs both namespaces, verifies no class key/ciphertext remains, and persists completion. Hash-chain audit records and authenticated retention state make crashes, retries, and remote request aliases observable. Removing the only live wrapped class key is cryptographic erasure for that run namespace, but `iorec` deliberately reports `physical_media_erasure_guaranteed: false`: snapshots, backups, copy-on-write storage, SSD remapping, plaintext exports, and already uploaded copies remain separate retention domains.

`export --format platform` is also an explicit declassification boundary: it verifies and decrypts the entire run into a mode-`0600`, at-most-5-GiB tar so the platform importer never receives the master key. That tar contains plaintext event envelopes and payload blobs. Temporary plaintext stays in a private file beside the destination and is removed on success or failure; the final path is published atomically without overwrite. Operators must protect and delete the result like pcap plus TLS keys.

`upload` is distinct: it reads encrypted local evidence, verifies it, and sends plaintext event batches and ordinary body blobs only over HTTPS unless `--allow-http` is explicitly acknowledged for a controlled local network. Pcap and TLS-secret blobs are excluded from every ordinary upload/backfill plan, and persisted legacy plans are sanitized before any network request. Supplying those tiers to the platform requires the explicit plaintext bundle export/import boundary above; there is no implicit sensitive upload path. Platform credentials are accepted only from a non-symlink mode-`0600` file; project credentials are replaced with a one-hour collector session in memory, never written into `.upload/` state. Fixed batch hashes and server `durable_seq` are revalidated on every resume. A platform-configured run cannot be pruned until every event is remotely acknowledged and the Recording is sealed.

The bundled platform authenticates tenant/project scope from credentials, caps all request bodies and archive expansion, rate-limits authenticated projects per API replica, and serializes project storage quota reservations through PostgreSQL advisory locks. Filesystem objects use path confinement, fsync, and no-replace publication; S3 uses conditional creation. Both backends are read-verified before catalog commit so an orphan object cannot silently bind different evidence. Multi-replica deployments still require shared unauthenticated/rate/bandwidth controls at the ingress, managed PostgreSQL/S3 hard quotas, TLS termination, backup, and key-management policies.

File and directory exports are published with Linux `renameat2(RENAME_NOREPLACE)` after their contents are synced. This makes successful publication a single no-overwrite namespace operation; destination-directory sync is still required before the command reports success.

## Audit boundary

The runs-root audit file is append-only during normal operation and every record commits to its predecessor with SHA-256. Every append verifies the complete existing chain while holding the file lock, so a corrupted historical prefix cannot be silently extended. Verification detects local truncation, modification, reordering, and partial tails. The chain has no keyed MAC, signature, remote witness, or WORM backing; an attacker able to rewrite the whole file can construct a replacement chain.

The whole-run event and blob budgets count physical storage, including encryption framing and orphan files. Blob count is also atomically limited to the same 250,000 entries accepted by inspection. Event writes enforce the reader's 24 MiB per-record recovery limit before persistence. Budget, file-count, or recorder persistence failures increment capture-drop state and do not abort an otherwise healthy proxied HTTP or WebSocket exchange; cleanup and manifest finalization use the durable prefix after writer failure.

Process discovery refuses task trees above 65,536 processes, per-process descriptor sets above 262,144 entries, aggregate scans above 262,144 connections or 65,536 gap observations, and cross-run gap identity history above 10,000 entries. It records same-PID executable changes, emits one incomplete limit terminal, and counts subsequent omitted gap observations without unbounded memory growth. Its final event reports the full count of still-running processes but serializes at most 1,024 sorted PIDs. Exceeding a scan boundary is a recorded capture failure, never evidence of complete coverage.

The root command's exit ends recording. Surviving descendants are not killed automatically; any observed survivors or open connections make the tracker terminal incomplete, increment capture loss, and add a manifest gap for uncaptured post-boundary activity.

## Network behavior

The reverse proxy never follows upstream redirects and strips hop-by-hop headers while preserving provider authentication. It is a recorder, not an authorization gateway. Default packet capture is filtered to a bounded launch-time snapshot of numeric upstream addresses; it can include unrelated traffic to a shared address, miss later DNS changes, and cannot establish absence of bypass.

`--task-netns` is a separate fail-closed Linux boundary. A stopped target first enters distinct user and network namespaces through fixed root-owned helpers and subordinate ID mappings. Before the real executable is released, the recorder preserves its original UID/GID but locks `NoNewPrivs`, clears effective/permitted/inheritable/ambient/bounding capabilities, disables IPv6 and DNS, and installs an nftables output chain whose default is drop and whose only non-loopback accept rule is IPv4 TCP to the exact recorder gateway/port. The slirp4netns helper must enable both its sandbox and seccomp filter. tcpdump runs inside that namespace, captures all IP traffic in immediate mode, and keeps the namespace alive for final verification. Firewall/sysctl state is checked before and after the target window and at shutdown; regressed counters, policy mutation, helper failure, capture loss, post-window traffic, or any denied target packet prevents a complete transport audit. This mode intentionally breaks targets that need unrelated network services and is not a general-purpose sandbox: the target still has same-user filesystem/IPC authority outside the network namespace.

`--transparent-proxy` extends that boundary without adding general DNS or egress. It requires a non-truncated, non-loopback IPv4 launch snapshot, creates a distinct mount namespace as temporary namespace root, bind-mounts a recorder-created `/etc/hosts` snapshot read-only, then drops back to the invoking UID/GID with no capabilities before the second launch barrier. Loopback, unspecified, multicast, and broadcast endpoints fail before target launch; in particular, Linux loopback output DNAT does not traverse the rootless slirp path reliably. Numeric nftables rules DNAT only the configured original model sockets to the recorder; rule shape and redirect counters are verified from the complete private ruleset. HTTPS identities use fresh ECDSA keys per run. Generation-time CA and leaf key buffers use `Zeroizing<KeyPair>` on every return path; rustls' AWS-LC provider independently wraps the leaf DER while loading its in-memory signing key. No private key is written. Only the public CA is written, at mode `0600`, for the target trust variables, and both temporary public files are removed after namespace shutdown. The transparent listener caps concurrent pending handshakes at 128 and each handshake at ten seconds. Certificate pinning, custom resolvers/trust stores, QUIC, DNS churn, same-user file tampering, core dumps, swap, and surviving descendants remain outside the claim. Use OS process isolation and memory-hardening controls when the target is hostile.

A successful payload diff alone never establishes complete capture. `transport-audit` schema v3 limits its claim to `target-network-namespace-ip-transport`; same-user Unix-domain IPC/shared daemons, Agent lifecycle semantics, server-hidden state, and host-wide traffic are outside that boundary. Within it, the auditor requires strict task-egress scope, verified proxy-only or exact transparent model routing, zero unknown/bypass/QUIC/unparsed surfaces, terminal attempts, complete proxy bodies, zero capture/decoder loss, and exact request/response multiset agreement. HTTPS transparent mode additionally requires recorder key logs to decrypt the captured TLS streams; only then is an unknown target-side TLS library irrelevant to transport integrity. Logical Agent-anchor correlation remains reported but is not used as transport evidence; the auditor independently pairs proxy attempts with decoded streams by their complete body signatures.

The process tracker compares observed target sockets against a bounded launch-time DNS snapshot of the configured model upstream. A match outside the recorder listener is explicit `model_bypass` evidence and fails transport verification. DNS churn, SNI, shared CDN addresses, and connections missed between `/proc` polls remain declared limitations; the classifier never grants completeness.

Repeatable `--egress-rule auth|telemetry|update|other=HOST:PORT` entries provide conservative labels for expected auxiliary target sockets. Parsing rejects credentials, paths, queries, fragments, implicit/zero ports, control characters, and IPv6 zone IDs. Resolution is bounded and concurrent, happens before target release, and is persisted as recorder-owned evidence. DNS failure, model-address collision, or cross-class socket collision aborts launch. Offline inspection accepts only the fixed class vocabulary and maps a missing or invented label to `unknown_external`; the connected platform independently repeats that fail-closed reduction from immutable process connection events. These rules do not authorize traffic, authenticate a hostname, verify SNI, or upgrade shared-host completeness. They conflict with `--task-netns`; both its proxy-only and transparent variants deliberately permit no auxiliary IP endpoint.

## Reporting vulnerabilities

Do not include real prompts, credentials, TLS secrets, or run bundles in a public report. Provide a minimal synthetic reproducer and the `iorec --version` output through the repository host's private security-reporting channel.
